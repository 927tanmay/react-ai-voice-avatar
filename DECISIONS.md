## Dynamic Neural TTS Engine (Kokoro-82M vs Meta MMS)
- **Problem**: Meta MMS-TTS (`Xenova/mms-tts-eng` / `hin`) provides functional localized speech synthesis, but uses a flat, monotone voice architecture with zero prosody or emotional variance—leading to a robotic conversation feel.
- **Solution**: Integrated **Kokoro-82M ONNX** (`kokoro-js`) as our high-fidelity English voice engine, capable of rich intonation, conversational breathing, and multi-voice profiles (e.g., `af_heart`, `am_michael`, `af_bella`).
- **Dynamic Switching via Props**: Added `ttsEngine?: 'kokoro' | 'mms'` and `ttsVoice?: string` to `IndicAvatarProps`. Developers using our React component can govern the active synthesis model cleanly through props and toggle between engines seamlessly during live runtime via automated worker message dispatching (`switchTts`).
- **WebGPU Acceleration with WASM Safety Net**: Kokoro is instantiated with `dtype: "q8"`, prioritizing WebGPU execution and automatically falling back to WASM when running on legacy hardware.

## Phase 4 Completion & Voice-Native Pipeline Optimizations
- **Dual-Worker Architecture (`mlPipeline.worker` & `kokoroTts.worker`)**: Separated Kokoro-82M TTS into a standalone Web Worker (`kokoroTts.worker.ts`) away from the main ASR+LLM+MMS worker. This isolates `kokoro-js`'s heavy Emscripten/WASM vocabulary tree and prevents worker bundling conflicts.
- **Vite Dependency Exclusions**: Added `optimizeDeps.exclude: ['kokoro-js', 'phonemizer']` in Vite configs to prevent Vite from pre-bundling Emscripten WASM filesystem references.
- **WebGPU FP32 Acceleration & Low-Latency Streaming**: Upgraded Kokoro execution to `device: "webgpu", dtype: "fp32"` and lowered sentence dispatch thresholds from 35 chars down to 5 chars when Kokoro is active, reducing speech kickoff latency to milliseconds.
- **Voice-Native System Prompts & Speech Sanitization**: Replaced default written-assistant style system prompts with human conversational directives (enforcing brevity, contractions, and zero markdown). Added `sanitizeForSpeech` across workers to automatically strip residual markdown symbols and convert numeric ranges (e.g., `620-800` -> `620 to 800`) into words for smooth TTS prosody.
- **Synchronized State Completion (`isEndMarker`)**: Implemented an end-to-end completion signaling mechanism between the ML and Kokoro worker queues, ensuring the avatar cleanly transitions from `speaking` back to `idle` and reactivates VAD microphone listening as soon as speech finishes.

## Phase 5 Completion & Audio-Visual Lip Sync Architecture
- **Language-Agnostic Viseme Dictionary (`visemeTable.ts`)**: Designed a universal O(1) character-to-viseme lookup table mapping English (Latin), Hindi (Devanagari script, matras, and Perso-Arabic nukta loans) directly to 17 canonical viseme targets with tuned ARKit blend shape weights. Adding future languages simply requires appending character keys without modifying core math.
- **Dedicated Retroflex & Aspirated Articulation**: Resolved typical lip-sync uniformity across Indian phonotactics by establishing dedicated blend profiles:
  - `DD_RETRO` (ट, ठ, ड, ढ, ण): Increases lower jaw drop and subtle lip retraction to simulate tongue curling.
  - `ASPIRATE` (ख, घ, छ, झ, थ, ध, फ, भ): Emphasizes wider lip funneling and burst airflow clearance.
- **Hybrid Audio-Text Blending Engine (`phonemeTiming.ts` & `audioLipSync.ts`)**: Because pure spectral frequency cannot reliably distinguish aspirated/retroflex consonants from steady waveforms alone, we built a hybrid engine. Real-time FFT audio energy from `AnalyserNode` drives **how wide** the mouth opens, while duration-scaled text timestamps determine **what shape** the lips take via binary search across the phonetic timeline.
- **Zero-State R3F Animation Loop**: Connected the hybrid lip-sync calculations directly inside `@react-three/fiber`'s 60fps `useFrame` rendering loop. Viseme weights are mutated directly on `meshRef.current.morphTargetInfluences` using mutable references, explicitly bypassing React component state to prevent UI rerender penalties or frame stutter during concurrent LLM/TTS generation.

## Live Avatar Dynamics & Interactive Pointer Tracking
- **Autonomous Facial Vitality (`avatarDynamics.ts`)**: To prevent unnatural, rigid staring during idle and active conversational periods, implemented an independent procedural dynamics engine running alongside lip sync at 60 FPS without React state modification:
  - **Spontaneous Blinking & Saccades**: Computes randomized interval timers (3–5s) with sine-curved eye closures (`eyeBlinkLeft/Right`) and micro-saccade eye darting (`eyeLook...`, `eyeSquint...`) to simulate active human focus and environmental attentiveness.
  - **Acoustic Upper-Face Coupling**: Real-time vocal RMS and frequency band energy dynamically elevates inner/outer eyebrow muscles (`browInnerUp`, `browOuterUp...`) and subtle cheek activation on vocal emphasis spikes during speech output.
- **Interactive Cursor & Pointer Tracking**: Utilized R3F canvas pointer coordinates (`state.pointer`) within `useFrame` to calculate physics-damped rotational vectors toward user mouse movements and touch UI interactions.
  - **Humanoid Armature Bone Lookup**: During scene parsing, the engine identifies standard skeletal neck or head bones (`Head`, `Neck`, `Head_01`). It smoothly rotates the actual armature joint toward the cursor within anatomical turning tolerances (±25° horizontal yaw, ±14° vertical pitch), maintaining responsive eye contact and physical immersion.
- **Future Scope & Community Contributions**: Advanced state-driven behavioral posture shifts (e.g., active listening empathy nods, thinking glances) and skeletal body mechanics (thoracic breathing armatures and `@react-three/drei` `useAnimations` conversational hand gestures) have been designed and reserved as targeted community contributing guidelines and open roadmap issues for post-release development.

## Zero-Config npm Package & 13-Point Architectural Refactor
- **Regex Externalization & Bundle Self-Containment**: Replaced static array matching in `rollupOptions.external` with a function/regex matcher `(id) => /^(react|react-dom|three|...)/.test(id)` to prevent `react/jsx-runtime` from being embedded into the consumer package (which previously caused dynamic `require("react")` dev server failures). Removed worker-level external declarations so that Web Workers compile as self-contained bundles without requiring consumers to configure complex bare module import maps in the browser.
- **Worker Instantiation & Runtime Emscripten Recovery**: Standardized worker initialization across `useKokoroWorker` and `useMLWorker` using standard ECMAScript `new Worker(new URL(..., import.meta.url), { type: 'module' })` wrapped in comprehensive error boundary diagnostics (`onerror` and `onmessageerror`). Removed the invasive `scripts/fix-phonemizer.cjs` postinstall hack entirely; replaced it with a self-contained runtime warmup loop and auto-retry handling in `kokoroTts.worker.ts` to cleanly tolerate asynchronous Emscripten dictionary extraction (`Invalid language identifier: "en-us"`) during production CDN execution.
- **Dynamic Lazy Loading & Asset Ergonomics**: Removed static top-level imports for `leva` and `@ricky0123/vad-web`, moving them to dynamic imports (`React.lazy(() => import('./LevaDebugPanel'))` and `import('@ricky0123/vad-web')`). This reduces primary consumer bundle size to ~42KB (12KB gzip) when debug tools are inactive. Made HTTP HEAD checks for local `/ananya.glb` assets opt-in via `enableLocalAssetProbe: false` by default to avoid console 404 spam in SPA setups, and added `vadAssetPath` and `onnxWasmPath` props for seamless self-hosting in restricted or airgapped network environments.
- **CI Bundle Integrity Validation**: Created `scripts/smoke-test.js` and wired it into `"test:smoke"`, ensuring automated assertions pass before shipping new releases.

## Unfreezable Audio Pipeline & Production TTS Resilience
- **Unfreezable Main-Thread Audio Engine & Poison-Pill Guard ([useAiVoiceAvatar.ts](file:///Users/apple/Documents/my/react-indic-avatar/src/hooks/useAiVoiceAvatar.ts))**: Prevented pipeline deadlock by adding an immediate zero-length / invalid sampleRate check before `createBuffer`, completely eliminating synchronous throws when processing forwarded text chunks or stripped emoji phrases. Wrapped Web Audio API initialization in a robust `try/catch` block that resets playback state and recurses on failure. Implemented a 10-second queue watchdog timer (`playbackWatchdogRef`) that automatically recovers stranded speaking states to `idle` and re-engages the VAD mic if worker generation stalls or connections drop in production.
- **Worker Failure Reporting & WebGPU Timeout Boundaries ([kokoroTts.worker.ts](file:///Users/apple/Documents/my/react-indic-avatar/src/workers/kokoroTts.worker.ts))**: Replaced silent error swallowing with guaranteed structural stream reporting—every failed non-last chunk now emits a fallback zero-sample message to ensure main-thread queue progression. Wrapped all `kokoroTts.generate()` calls in a `Promise.race` timeout boundary (30s for standard generation, 8s during warmup) to convert GPU device hangs into reportable, self-recovering stream continuations.
- **Stranded Task Recovery & Pictography Sanitization**: Added automatic queue execution (`processTtsQueue()`) immediately upon broadcasting worker initialization readiness, resolving dropped synthesis tasks queued during initial CDN weight pulls. Enhanced `sanitizeForSpeech` to strip Unicode pictographs (`\p{Extended_Pictographic}|\p{Emoji_Presentation}`), eliminating ~2.5s of vocal hallucination babble previously generated when conversational LLM personas appended emojis to sentence boundaries.
- **Engine-Aware ML Worker Initialization ([mlPipeline.worker.ts](file:///Users/apple/Documents/my/react-indic-avatar/src/workers/mlPipeline.worker.ts))**: Fixed language switching equality evaluation and guarded `switchTts` to ensure Meta MMS TTS models are only instantiated when `currentTtsEngine !== 'kokoro'`, eliminating redundant network downloads during voice selection in Kokoro sessions.
- **Output-Based Espeak Warmup Verification ([kokoroTts.worker.ts](file:///Users/apple/Documents/my/react-indic-avatar/src/workers/kokoroTts.worker.ts))**: Replaced simple exception catch loops during worker initialization with definitive audio duration testing against a known sentence probe (`'The quick brown fox jumps over the lazy dog.'`, which yields ~5.1s when espeak is operational and ~0.53s when voice tables are uninitialized). Rather than relying on absence of thrown errors (which failed when legacy patches forced identifier validation), the initialization sequence requires probe audio output to exceed `2.0s`, cleanly retrying until asynchronous Emscripten decompression completes, and terminating the worker cleanly on failure.
- **Relative Worker Asset URL Generation (`base: './'`)**: Configured library build with `base: './'` in `vite.config.ts` so that worker URLs emitted by Rollup do not contain leading slashes (`new URL("assets/kokoroTts.worker-<hash>.js", import.meta.url)`). This guarantees worker scripts resolve correctly inside consumer `node_modules/react-ai-voice-avatar/dist/` directories rather than hitting 404s against domain site roots.
- **Self-Contained Worker Bundling (`codeSplitting: false`)**: Configured worker rollup options with `codeSplitting: false` to force all dependency code directly into individual worker scripts. Because consumer bundlers treat imported workers as opaque assets and do not copy sibling chunks (`./kokoro-xxx.js`), inlining dynamic dependencies prevents runtime worker chunk 404s.
- **Eliminating Base64 WASM Bloat (`excludeOnnxWasmPlugin`)**: Built a zero-overhead Vite pre-plugin in `vite.config.ts` that intercepts static `.wasm` asset constructor patterns (`new URL('xxxx.wasm', import.meta.url)`) inside ONNX Runtime Web and replaces them with clean CDN references. This completely stopped Vite from base64-inlining 130 MB of unused WASM binaries into worker bundles, reducing our published NPM package size from ~52 MB tarball (~195 MB unpacked) down to a lightweight 1.2 MB tarball (~3.3 MB unpacked).
- **Esbuild Worker Pre-bundling for Emscripten Order Preservation ([build-workers.mjs](file:///Users/apple/Documents/my/react-indic-avatar/scripts/build-workers.mjs))**: Resolved persistent 0.53s "espeak voices not loaded" silent audio generation blips caused by Vite 8 / Rolldown reordering Emscripten module data dependency evaluation inside `phonemizer`. Created a dedicated esbuild post-compilation workflow (`scripts/build-workers.mjs`) that pre-bundles `kokoroTts.worker.ts` and `mlPipeline.worker.ts` directly into `dist/assets/*.js` with stubbed Node.js built-ins and preserved top-level Emscripten evaluation order. In library builds, `usePrebuiltWorkersPlugin` switches worker import paths to static `assets/*.js` strings without activating Rolldown recompilation, ensuring consumer bundlers copy our pre-bundled worker assets untouched into their production distributions.
- **CommonJS VAD Pre-bundling Inclusion in Vite Dev Mode**: Added `include: ['@ricky0123/vad-web']` alongside `exclude: ['react-ai-voice-avatar', 'kokoro-js', 'phonemizer']` across documentation and example Vite configurations. While excluding our package keeps `import.meta.url` properly targeting shipped worker assets in dev mode (`npm run dev`), excluding transitive dependencies prevents Vite from converting CommonJS packages to ESM. Explicitly including `@ricky0123/vad-web` resolves browser `ReferenceError: exports is not defined` crashes and ensures consistent microphone initialization in consumer dev environments.
- **Verbatim Worker Copying & AST Shielding ([vite.config.ts](file:///Users/apple/Documents/my/react-indic-avatar/vite.config.ts))**: Prevented consumer bundlers (Vite/Rolldown/Rollup) from re-processing pre-bundled esbuild workers during consumer application production builds (`vite build`). When consumer bundlers encountered inline worker instantiations (`new Worker(new URL('...', import.meta.url))`), their Worker plugins re-compiled the script (altering byte size from 2,633 KB to 2,599 KB and breaking Emscripten initialization order). By wrapping the URL construct in `String(...)` alongside a `?url` asset parameter during library build (`new Worker(String(new URL('assets/kokoroTts.worker.js?url', import.meta.url)))`), worker AST bundling matchers ignore the call while static asset handlers copy the esbuild artifact verbatim into consumer production distributions.
- **Worker Re-creation Over Same-Instance Retry ([useKokoroWorker.ts](file:///Users/apple/Documents/my/react-indic-avatar/src/hooks/useKokoroWorker.ts))**: Because `espeak-ng` permanently caches empty voice tables inside C memory when evaluated before DecompressionStream extraction finishes, retrying `generate()` on the same instance always yields 0.53s diagnostic audio blips. Replaced same-instance retry loops with immediate termination (`recreate_required` signal), cleanly tearing down the WebAssembly memory heap and spawning a fresh Worker instance after an exponential backoff until dictionary extraction completes.
- **Build-Time & Runtime Worker Integrity Assertions ([build-workers.mjs](file:///Users/apple/Documents/my/react-indic-avatar/scripts/build-workers.mjs))**: Added SHA-256 digest computation and byte size assertions to `scripts/build-workers.mjs` during package compilation. Instrumented `kokoroTts.worker.ts` with runtime script self-fetching (`self.location.href`) to log SHA-256 hashes and explicitly alert developers in DevTools if bundlers inadvertently modify or code-split the worker asset below the expected 2MB threshold.
